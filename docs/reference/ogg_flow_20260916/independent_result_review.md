# Flow 机制实验独立结果复核

日期：2026-09-16。本复核在正式开发集读取已获授权后完成，仅新增审查文件，未改冻结实现、参数或实验数据。

**本轮支持受约束动作邻域内存在有用的评分方向，没有证明 QGF 式注入比原 velocity 参数化更好。** 最终命令约束与 XYZ/夹爪分组处理影响很大；这些因素同时变化，尚不能把改善单独归因于“强度过大”，也不能把负结果归因于梯度符号错误。

## 1. 独立核对范围

从 30 个正式源的 **1,920 份分支 summary** 独立重建 `30×8方法×8后缀` 结局数组，再核对 `evaluation.json` 与 `per_source.csv` 的全部 240 行。逐一检查每臂成功率、配对收益、救回/损害、六个预登记比较、预测值及真实收益。

独立 NumPy 复算 bootstrap，没有调用项目的 `estimate` 或 `summarize_rows`：按照任务名称排序，每个任务对六个完整源有放回抽样，源内八个配对后缀一起保留；汇总30个源均值，10,000次重复，随机种子29015，取2.5%与97.5%分位。所有成功率及收益区间与主评估**精确一致**。这些是未作多重比较校正的名义95%区间。

完整输入 SHA、逐指标复算结果见 [independent_result_review.json](independent_result_review.json)，共记录1,925个输入文件身份。本轮30源全部报警，没有无报警源或预算截短前缀；每臂分母240，独立统计单位仍是30个源。

## 3. 对用户核心问题的回答

**局部方向得到支持。** 在固定实际命令幅度与分组度量后，正向 direct 明显优于反向和结构化随机。因此不能把当前 critic 的所有局部动作梯度概括为方向错误。这一结论限于本次开发源分布及预登记投影方式。

**没有证明改变 flow 注入参数化本身带来优势。** 去掉额外 τ 因子的 direct 与 velocity 同为 +5.83 点，二者差的区间很宽并跨0。post 点估计比 direct 高3.33点，但该差的名义区间为 [−1.25,+10.42]；不能据此宣称 flow 注入已被证明劣于终点修正。解析和实际 sampler 预检已核对上升符号，现有结果没有支持“符号写反”的解释。

**最终命令处理很重要，但因果成分尚未拆开。** 原生 direct 为 −17.50点，命令匹配后为 +5.83点；匹配同时改变最终幅度、边界可行坐标与 XYZ/夹爪比例。它支持这一组约束有实际意义，但没有单独识别“仅降低 XYZ 幅度”或“仅放大夹爪微调”哪个因素贡献最大。原生与匹配方法必须保留不同名称。

## 4. 有用方向不等于准确的逐源收益评分

| 方法 | 平均预测收益 | 平均真实收益 | 逐源预测/真实收益 Pearson |
| --- | ---: | ---: | ---: |
| direct，命令匹配 | +10.19点 | +5.83点 | −0.1633 |
| post，命令匹配 | +10.70点 | +9.17点 | −0.1991 |
| 原生 direct | +25.54点 | −17.50点 | +0.0907 |

原生 direct 把 Q 推得更高，却损害了实际成功率，说明评分不能跨幅度直接当作可信改进量。post 的总体平均预测接近真实均值，也没有带来准确的逐源收益排序。观测到的负相关来自30源和每源八次后缀，不足以证明稳定的反向规律；准确表述是**本轮未支持用 ΔQ 大小可靠识别哪些源获益更多**。

局部梯度相对反向/随机有用，与概率校准、逐源排序、大幅动作可行性，是不同性质，必须分别评价。

## 5. 结论边界与后续冻结

post 的开发点估计 +9.17 点超过约 +5 点目标，但它是多个开发方法中的最好点，不能称独立验证成功。其区间下界 +1.25 点也没有确立“至少提升5点”。

post 在6源正收益、2源负收益、22源零收益；净增加22次成功，其中 shelf-place贡献12次、stick-pull贡献8次、disassemble贡献2次。pick-place-wall与stick-push的 a0 已各48/48，保留在总体分母中。小样本和任务天花板限制了结论范围。

夹爪分组归一可能强烈放大原生很小的方向分量，预检已单独记录；因此本次方向性结果对应注册的分组度量。若将 post 选为未来确认的主方法，必须连同计算共同可行半径所需的其他候选方向一起冻结。删除这些依赖以获得更廉价的纯 post 实现，会构成新算法版本，应另行验证。本复核没有追加仿真或运行未来确认实验。
