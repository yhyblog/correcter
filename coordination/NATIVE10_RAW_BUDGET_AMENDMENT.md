# Native10：raw 命令语义与独立恢复预算补充

日期：2026-09-16；版本1。分析端批准。本文补充并优先于 TASK/ADDENDUM 中有关命令投影和预算的表述；不修改旧实验代码/产物，不改变 native10、600/100/50/50、训练两轮与候选/repeats。主采集/训练仍未放行。

## 1. 新 native10 命令语义

批准执行端采用：`replan = raw_a0`，`corrected = raw_a0 + matched_delta`。正常 native10 队列和后缀也保留正常 raw 命令接口。不能在 replan 上额外施加整体投影，再把这种变化算作报警收益。

令 `r = raw_a0`，`C(r) = clip(r, -1, 1)`。当前冻结 critic 仍用原 ActionTransform/T 所定义的 clipped 表示；所有评分候选必须对应实际 raw 候选经同一映射后的值。P0 前的 CPU/整合检查及 P0 实际候选 bank 审计应覆盖：

- 零 delta、replan 和未修改坐标保持 raw 锚点；十步以外 tail 不变。纯恒等路径要求逐位一致。
- 修改只能发生在原可行 mask `1 - |C(r)| >= .05` 内；不能仅排除 `|r| >= 1` 而遗漏近边界区。
- 对允许修改的坐标，检查 `C(r ± delta) = C(r) ± delta`，及实际执行差与用于 critic 评分、范数统计的差一致；非恒等浮点运算用预登记容差，不在看到结果后放宽。
- 正反对共享 mask 和对称可行半径，半半径来自相同 delta/2；不得分别裁剪后仍声称正反对称。训练13候选中的零通道不得压低其他方向的半径。
- 梯度仍通过真实 T/clamp 导数，post 保持原 S² 梯度转换，禁止用直通导数替换；a0 锚点 R(a0)=0 保持。
- 保存 raw_a0、critic_a0、mask、构造 delta、最终 raw 候选、实际 critic 候选、实际范数及退化原因。候选去重不能只凭 clipped 数组推断 raw 命令可复用。

这是一项明确的新 native10 协议语义。**旧 anchor 的跨实现诊断继续使用旧 bounded 命令与旧随机流**，不能在同一次迁移比较中换成新 raw 协议。

## 2. P0 核对实际作用量，避免凭单层代码判断

只读审查发现：MetaWorld Python 层显式裁剪 XYZ、将 gripper raw 送入 simulation；五任务所用 XML 的夹爪 actuator 同时声明 `ctrllimited=true, ctrlrange="-1 1"`。两项证据均不能单独代替当前加载模型的实际检查。

P0 在现有600上限内：

1. 保存五任务实际加载的 actuator 限制、相关 disable flags 和模型身份。
2. 在相同恢复状态下，以预登记的正/负饱和 gripper raw 及 clipped 对照做少量一步/短前缀检查，覆盖可获得的接触状态。检查 qpos/qvel、实际执行力、接触和终止/成功，不要求原始 data.ctrl 数值一致。
3. 记录真实候选的 raw 越界频率/幅度及评分映射一致性；额外 probe/restore 全部进入 P0 ledger。

若限制实际生效、物理等价及表示不变量通过，当前 clipped critic 不因 raw 越界而构成该项阻塞，无需仅因此增加模型输入维数。即便内部饱和等价通过，主臂仍保留批准的 raw 接口。

若同一 clipped 表示实际产生不同物理效果，允许完成定位诊断，但大规模主采集/训练不得直接沿用有盲区的表示；须先明确有效动作表示或加入缺失 raw 信息，再更新冻结配置。reward 数值差异与二值成功/动力学差异分别记录。

## 3. 独立 bank 恢复需预留1000次

原计划47600包含800次 source capture，但没有包含独立 `candidate_restore`。现按最保守、不预设复用的上界补齐：

| 独立 bank 恢复用途 | 上限 |
|---|---:|
| 训练600个 source | 600 |
| 开发100个 source 的局部标签 bank | 100 |
| 两轮开发新 critic 比较，各100个 source | 200 |
| 校准50个 source | 50 |
| 保留50个 source | 50 |
| 合计 | 1000 |

因此主计划 **47600 + 1000 = 48600**，从原2400技术储备显式拨付1000，剩余 **1400**。总硬上限仍为 **50000**。P0的独立 bank 恢复已包含在其600上限内，不另加到1000项。

各阶段计划上界（包括所在阶段的 source capture 和独立 bank 恢复）：

| 阶段 | 计划上界 |
|---|---:|
| P0 技术诊断、anchor、预检、复现及失败 | 600 |
| 第一轮300训练＋100开发局部标签 | 23200 |
| 第一轮实际开发比较 | 2100 |
| 第二轮300训练局部标签 | 17400 |
| 第二轮实际开发比较 | 2100 |
| 校准 | 1100 |
| 最终保留 | 2100 |
| 计划合计 | 48600 |
| 剩余技术储备 | 1400 |
| 总硬上限 | 50000 |

计费定义：独立 source capture、独立 bank restore、实际 branch、单独复现/probe 均逐项入账；branch 自身为续跑而执行的内部 restore 已包含在该 branch attempt，不能重复计为 bank restore。技术失败/原源重试保留每次 attempt 及错误；不能按成败重采或换源。无报警、不需 bank、合法候选复用只能减少实际计数，不能预先假定这些节省必然发生。

G0仅利用现成状态/标签离线训练不新增仿真；若改cut后独立恢复、重捕获或增加闭环验证，则不包含在上述1000之内，需单列并先协调分配剩余储备或缩减其他开发成本，不能暗中增加总预算。
