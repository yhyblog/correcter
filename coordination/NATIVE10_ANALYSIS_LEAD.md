# 自主迭代分工与分析决策

2026-09-16。用户明确授权两个对话继续自行迭代，由分析端主导，分析端注意力集中于方法与分析，不接收大量实现代码。

## 1. 分工与权限

- 分析端决定研究目标、数据采样、训练/纠偏方法、开发选择、阶段放行与结论；以封存结果和不确定度为依据。
- 执行端负责所有实现、CPU检查、仿真/训练、并发性能、预算、重试原因、完整性审计、冻结和可重建产物。
- 必要的代码审查交给独立审查子任务；分析主线程只读结论、关键统计及证据路径。
- 已授权范围内的常规工程修复和调度由执行端处理；方法/数据目标改变由分析端判断，不重复向用户请求已有授权。总50,000次硬限、旧封存只读、GPU生命周期政策继续有效。
- 主采集按阶段READY控制；本授权不把当前P0-only READY自动扩大成main权限。

## 3. 训练cut的预登记fallback决定

此条只用于尚未采集的训练episode，解决主采集前的未定项，不改P0：

- 仍为50%首次合法报警、50%scheduled；scheduled目标15/45/95按任务/轮次均衡。
- scheduled优先序分别为15→5、45→15→5、95→45→15→5。到达主目标就用主目标；若episode在目标前终止，只按该固定序列选择已记录且非终止、剩余预算足够的合法cut。
- 首次报警组使用第一次合法报警；整集没有合法报警时，仅训练可按15→5的固定优先序提取已记录合法cut。
- 如果没有合法cut，保留该episode及原因，不换seed、不重跑以取得更有利状态。fallback不能依据成功/失败标签、候选Q或反事实收益改变优先序。
- 保存requested_cut、actual_cut、selection_reason、alarm/scheduled/fallback三类计数及逐任务覆盖。fallback属于离线训练抽样，不声称是可部署触发器。
- 开发/校准/保留的主策略不使用这种事后fallback：无报警各臂保持正常native10并保留共同结局及总episode分母。

执行端在主采集注册/冻结时落实该规则，若当前capture无法保留必要的早期状态信息则报告实现限制；无需为此延迟P0。

## 4. 分析只围绕以下问题做迭代

| 证据 | 分析判断 | 后续方向 |
|---|---|---|
| native10下中断收益弱或有害，且G0排序与新目标不一致 | 首先审查触发目标/相位；小样本不显著不等于失效 | 利用已采continue/replan标签评估G0适配，或登记自然规划点纠偏新假设 |
| 随机/反向/通道候选能改善，而当前梯度选不中 | 动作评分或局部方向泛化有问题 | 优先局部数据、相对损失、全小critic重训；按source看救回/损害 |
| post方向有效，flow执行后失效 | 需检查注入时刻、中间动作估计及传播 | 以同实际扰动预算比较方法，记录中间查询距a0；限定少量开发变体 |
| XYZ-only较好、加入grip后损害增加 | 通道预算或夹爪时序可能不合适 | 依据开发证据调整夹爪预算/禁用规则，再冻结 |
| 当前候选族在大量失败状态上均难改善 | 十步窗口、介入阶段或候选族可能不足 | 分析覆盖与标签分辨率，必要时调整第二轮采样；不能声称所有动作都无解 |
| Q增益大而真实净增益持续接近零 | 预测/选择偏差尚未解决 | 不以Q上升宣布成功，不继续无约束增强引导 |

两轮训练按新600独立episode主计划推进。P0不是收益显著性门槛；第一轮后的方法变更须写明依据、预算及第二轮冻结版本。最终保留集只用于已固定策略的一次独立检查，禁止据其结果反复调参仍称独立验证。

## 5. 异步交接，避免用户手工转发

执行端在P0完成、第一轮数据/训练/开发完成、第二轮完成、校准/冻结完成、最终结果完成或真正阻塞时：

1. 更新NATIVE10_EXECUTOR_STATUS.json，写相应简短阶段报告。
2. 用已授权的 `codex queue --thread 01a0a551-9ed3-7f53-9f39-b60d8674819d --message ...` 通知本分析对话。若queue延迟，以共享文件和时间戳为准，不因旧消息重复运行。
3. 报告只含：阶段/版本、真实attempt及剩余预算、独立episode/有效cut数量、关键结果与区间、救回/损害、异常、成本、下一步建议及证据路径。不发送长代码或整段日志。
4. 分析端独立复核并更新READY/决策，向执行线程 `01a09fc3-ff82-72e3-87ef-9e9f63a792ce` 下达下一阶段指令。阶段间可继续无依赖CPU准备，不越过未放行的仿真/训练边界。

用户侧只汇报影响方法判断的阶段结果、方向变化和确需用户处理的约束；不把常规实现细节作为新的用户决策。
