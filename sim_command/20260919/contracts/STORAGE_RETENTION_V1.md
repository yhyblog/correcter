## 范围与保护

- 当前明确相关项目为 `Corrector`、`vla-corrector`；即使处于这两个目录，也须核实用途，不能整目录清空。其他 VLA 子项目须在清单中先确认归属。
- `embodied-ai-workspace` 是多项目工作区，不能整体作为 VLA 清理目标。只有确认属于本实验 VLA 子项目且无复用需求的具体数据/权重目录才可列入清单；环境、其他模型项目及来源不明的公共缓存不动。
- 清理前解析真实路径，防止符号链接跨出授权范围。不能沿链接删除其他项目或目录外的原文件；不能把路径包含 `vla` 作为唯一判据。
- 保留本轮需要的 π0.5/SmolVLA/X-VLA 底座、选定 Corrector 与 VLA-Corrector 权重、PCA/normalizer、训练初始化与必要续训状态、共用原始数据、冻结 split/source 清单，以及全部论文统计与审计所需的逐源结果、配置、代码身份、日志及资源账本。
- 已完成 standalone/native10 的封存证据及其 manifest 引用产物保留。历史训练过程的冗余大权重只有在确认不属于封存依赖、不再做选择/初始化/恢复后，才可清理。不能借清理重启旧实验。
- 正在训练、采集、下载、评测的文件，以及另一节点尚未确认不再使用的共享输入不能删。已创建 manifest 或 release 的路径必须先检查引用；不能只检查本节点进程就判断另一节点未使用。

## 两节点分工

1. A、B 在盘点/准备报告中记录各自磁盘可用量、主存及显存情况；三者分开报告。删除文件释放磁盘，不等价于释放主存/显存。共享挂载 `df` 可能展示池级容量，若项目配额未知则明确未知。
2. 两节点将清理候选写到各自 `receipts/<role>/STORAGE_CANDIDATES.json`，每条包括绝对路径、解析后的真实路径、项目归属、文件/目录类型、逻辑 bytes、用途、已完成/不再使用证据、依赖核查、替代保留产物（如有）、建议和风险。不扫描非 VLA 项目的内容。
3. 共享历史数据与权重由 A 统一执行清理；B 不独立删除共享历史资产。分析端根据候选发布精确路径清单，避免两端一边读取、一边删除。此为执行协调，不是向用户重问授权。
4. 本轮 `work/<role>` 中未被发布/引用、已关闭且确定无用途的失败临时文件或中间产物，也先报分析端决定，再由本角色按具体清单删除；禁止跨角色删除。是否丢弃训练 checkpoint 必须等选模完成并落实保存清单。
5. 清理先核验、后删除：只处理清单中的精确路径，核对类型/大小/身份未变，发现仍写入、引用不明或目标变更则跳过并报告。不得使用根目录通配符、全项目递归删除或按时间/文件名自动淘汰。
6. 写追加式清理回执到 `receipts/<role>/storage_cleanup/<unique_id>.json`：用户授权来源、host、UTC、每条路径、依据、删除结果、逻辑删除量、清理前后磁盘可用量及跳过原因。硬链接、稀疏文件、共享存储回收延迟会使逻辑删除量与实际释放量不同，分别报告。

## 后续训练与评测保存规则

- 训练仅保留预先约定的选定模型、最终模型及实际需要的恢复点；ensemble 成员、完整训练 seed 及不同损失分支分别保留，不能当重复权重合并删除。
- 不为每次评测复制同一底座权重；引用同一受保护资产。需要主机本地缓存时记录其来源与身份，缓存清理须另行满足授权路径范围。
- 默认保存结构化逐源结果和必要过程计数；不无差别保存全部逐帧视频、图像副本或大张量。原始训练轨迹及基线必需字段必须保存，不能为省空间破坏共同数据比较。
- 视频/大调试输出仅按发布单的固定样本策略保存；技术失败所需的最小诊断证据保留。测试阶段不能根据结果好坏选择保留哪些逐源记录。
- 每次正式 release 补充预计输入/峰值输出/临时空间、最低余量和产物保留规则。空间不足先停止新增写入并报告，不越界删数据或终止无关进程。

分析端的决定清单包含候选精确路径、`delete/keep/defer`、依据、执行角色与输入身份；只有 `delete` 条目可实际删除。执行端核验失败时跳过并反馈，不用近似路径替换。分析端不执行磁盘扫描或删除命令。

本规则不扩大模型 GPU 计算、仿真或训练预算；当前 P00 准备任务的这些计数仍为 0。
