# A/B/C 自主修复与阻塞跳过规则

依据：用户 2026-09-22 最新明确要求。适用于当前及后续已授权 Corrector 任务；发布即生效，不要求每次修复再向分析端请示。

## 1. 中止后先修复，再从未完成处继续

- 工程故障由本机执行端自行诊断：路径/序列化/依赖/进程退出/显存不足/队列元数据不兼容等，在不改变科学配置和数据范围的前提下，可以私有修复、降低实际并发、重启故障 worker 或接续队列。只做针对性 CPU 检查，直接使用原计划待完成 episode 验证，不增加独立 GPU 预检。
- 先查看原结果及进程族是否仍存活。终端断连、通知失败、旧消息重投不等于实验停止；健康任务不能重复启动。旧族确实退出或明确回收本机所属故障进程后，才释放/接续 claim。不得终止无关进程。
- 按 episode/unit 身份接续，保留成功和失败的**合法科学终局**；不得为提高成功率重跑失败任务，不重跑完成的训练、完整样本或整块包含已完成样本的 job。只有未启动或没有合法终局的技术失败单元可接续。先尝试从完整终局日志恢复，缺失费用保持 null，恢复来源单列。
- 保存原错误、修复摘要、受影响 unit、attempt lineage 和实际结果。旧失败不覆盖、技术失败不记为 success=false；修复若改变模型、动作单位、观察或环境语义，必须升级为科学决定，不能混入原配置。
- 同一故障默认最多两次**有明确修复依据**的自动重启/接续，计入已有阶段与节点 attempt 上限；禁止原样无限重试。同错仍出现或资源上限不足则记录问题并继续其他可执行任务。此规则覆盖当前未完成任务旧的“技术重试为 0/用完须逐次请示”流程，不复活已关闭的历史预检、取消的实验或已完成科学单元。

## 2. 需要分析决定时，上报并设置 30 分钟时限

- 本机写 `nodes/<A|B|C>/issues/<issue_id>.json`，至少包含 task/unit、首次上报 UTC、错误与已尝试修复、具体待决定事项、被阻塞任务、可继续任务、`analysis_response_due_at = reported_at + 1800s`、状态和相关证据路径。
- 通过现有共享 outbox 向固定分析原线程 `01a0b91f-355f-7cd1-ae36-412500534ffb` 投递一次；本机原执行线程保持完成/失败回调。投递失败不丢 issue，也不停止本机其他工作。不得用其他线程或递归回调替代。
- 分析端 30 分钟未给出可执行决定，自动设 `blocked_deferred` 并记录 `deferred_at`，保留问题及已得结果，继续扫描下一项**已授权、未完成、所有必要依赖已满足、归本机所有**的任务。消息送达、普通 ACK 或心跳不是实质决定，也不重置计时。
- 有独立任务时立即继续，不必等满 30 分钟。已得到决定时，在当前安全任务边界重新排入被阻塞任务；不打断健康计算、不制造重复单元。

## 3. 自动队列不能因一个问题整体闲置

- 调度器至少在任务完成/失败、依赖更新和 30 分钟期限到达时扫描可执行任务；轻量 CPU supervisor 负责计时和持久化，不让 LLM 用 sleep/tail 长期等待。就绪任务自动接续，不逐批等分析确认。
- 保持节点独立。跨节点任务只有取得明确 unit 所有权才能接手；不得以“加速”执行另一节点已 claim 的任务。
- 所有未完成项若均被真实依赖、资源、授权上限或截止时间阻塞，写 `NO_RUNNABLE_TASKS`，逐项说明障碍并上报；保留后台依赖监测。不得虚报正在运行，也不能为占 GPU 擅造实验。
- 最新科学顺序不变：**只按完整 Post 开发集选损失，固定部署 fit9101；选定后才做对应配置的后续测试。Velocity 沿用该配置并继续已授权实验，但不进入本篇最终表图。**30 分钟超时不授权跳过选模、使用部分开发集、用 test 选模或偷换配置。
- 本篇 Post 相关任务优先；独立准备、CPU 汇总和已授权无选模依赖的任务可填补等待。不得恢复剩余 475 采集、Random-multi 或旧配置已取消实验。

## 4. 运行中的兼容性与占卡规则

- 本规则作为附加控制面指令发布；不能替换正在运行链的 `priority_authorization`、task 身份或科学授权，不能为更新规则触发健康链 drain。原授权与新 followup 分开验证；仅把规则接入私有后续调度和故障处理。
- 目标每卡 3 worker、全机 24 worker；按实际 RAM/VRAM/IO 调整并记录原因。无必要不改变健康波并发。
- 整个 formal wave 包括加载、空档、先完成的卡，所有 holder 停算。故障时先确认本机 formal 全进程族退出，才恢复 holder；存在可执行任务时尽快正常交接下一项。不得与 formal 同时运行任何补位 holder。
- 不扩充既有科学样本、训练计划或总预算；必要技术接续计入实际消耗。新 admission 截止 2026-09-23 20:00 北京时间，最终表 23:00。容量/权限/无法安全停止本机故障族的问题不得绕过，应保留并转独立任务。

## 5. 执行端需交的最小回执

各节点消费本规则后写 `<NODE>_D24_AUTORECOVERY_QUEUE_RULE_V1_ACK.json`；将修复重试、issue 计时、跳过阻塞与接续逻辑接入自己的已授权有限队列，再交 RESULT，列实际部署位置、当前队列/原线程通知路径以及哪些只经过 CPU 检查。**规则 ACK 不冒充已验证真实故障恢复**。已有正常科学工作不因这项 CPU 控制任务等待。
