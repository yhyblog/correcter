# 评测并发更新：优先每卡3 worker，共24 worker

用户2026-09-22新增要求：每卡一个评测进程可能长期SM利用率低；用户报告SM≤20%超过2小时报警，连续报警超过12小时机器会关停。此处作为用户提供的运行约束记录，不声称已独立核实平台规则。

适用于A/B/C后续已授权评测。目标8张GPU每张3个常驻评测worker，共24个，使用实际GPU UUID分组；worker id 0..23不能直接当CUDA设备索引。每卡三个独立worker维持各自环境、队列、source/seed/claim，完成单元不能因增加并发重复执行。改变并发不改变模型、触发、动作单位或随机种子派生规则。

执行端进行普通本机容量检查：显存可用及已有模型实际峰值（未记录则明确估计）、RAM/cgroup限制、CPU线程及共享读取压力。能够容纳则在新队列使用24；有明确限制则使用实际可支持的最大并发（例如16），记录具体剩余量和每worker估计，不能无证据默认退回8。加载可分批并在首批已计划episode上观察内存；这不是额外GPU预检或吞吐实验。设置合理CPU线程数，避免24份加载/解码造成内存和I/O拥塞。若共享每卡策略服务，必须保证动作梯度路径、每source RNG及费用归属正确；不强制为并发增加新的算法改造。

当前已运行队列不直接改worker数量或身份。需要切换时由原执行端关闭新准入，保留已完成结果，排空当前单元/自有进程族，再用新独立入口对未完成且仍获授权的单元启动。优先结合本轮Q损失任务切换，避免单为调并发重跑或多次重载。

正式wave包括加载、间隙及尾部，全部holder计算必须停止；整族退出后恢复。不能在正式worker旁加holder，也不能为保持利用率开展未计划科学任务。只使用有限的常规监测，记录SM/显存/CPU/吞吐的采样范围；不得把瞬时值说成持续保证。后台有界队列、唯一claim、终局原线程通知和STABLE_HANDOFF规则不变，无需每批再次确认。
