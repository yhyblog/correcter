# 接口 v1 集成检查补充

分析端已核对发布文件 SHA。接口可以供 B10 立即接入；schema 未将事件次数限制为一次，也未固定 E8 动作维度。以下检查纳入当前 A10/B10 CPU 准备，不增加实验，不修改已发布 v1。

1. **E3 多次决策摘要。**完整原生频率由冻结配置及完整事件流定义；`event.decision_index` 记录多次决策。episode 的单值 `cut_step/entry_generation_id` 须注明摘要含义，不能据此限制 E3 原生调用次数。不适用时用 null 和原因；下游统计读取完整事件流。
2. **事件生命周期计数。**A10 明确 entered/returned/failed 各自 `resource_units` 是累计还是增量、同一 event 的唯一身份范围及终态缺失时的处理；完整调用只能记一次，容器事件不与子事件重复相加，部分失败不能把实际已进入的工作计为零。交“成功返回、部分失败、缺少末事件”三个 CPU 合成计数例子即可。B 与 A 使用同一汇总规则，不各自解释。
3. **缺失结果。**技术失败和未完成保持 null，未知终局不能训练成失败标签。P20 将冻结恢复规则与最终结果分母；保留计划数、完成数、技术失败数，不能静默丢弃 null 后把剩余完成集冒称完整配对测试集。无报警和提前成功的已完成样本保持在分母中。
4. **E8。**以后各 E8 release 绑定独立 H/C、动作维度及方法协议；不套用 Core MetaWorld 的生成50/C10设置。

A/B 的简短兼容性反馈与最终回执引用本文件。若现有 schema 无法表达所选规则，再由 A 发布 v2；不要覆盖 v1。
