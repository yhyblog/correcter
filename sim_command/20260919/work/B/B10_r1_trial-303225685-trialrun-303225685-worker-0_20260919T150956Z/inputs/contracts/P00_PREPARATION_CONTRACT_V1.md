# P00：公共方法与接口准备合同 v1

本合同只冻结A10/B10并行准备所需的科学口径。实际环境路径、原始数据字段缺口、checkpoint与公开近邻版本以A00/B00回执填入配套manifest。配套P00_PREP_V1仅放行CPU接口准备，要求各节点先完成自身盘点回执；不启动训练、模型GPU推理或仿真。

## 1. 固定方法和范围

- 外部方法主比较只用π0.5＋MetaWorld MT50、H10。Core方法为N、R、Post、Velocity；VLA-Corrector为直接基线，另锁定一个公开critic引导近邻。
- E4只扫H={10,20,30,40,50}；C=10、monitor_interval=5、max_interventions=1、total_env_steps=300、π0.5生成50和flow10保持固定。
- R/P/V均在首次合法G0报警后执行新动作前10步，之后重新生成并恢复nativeH；不能继承新计划未执行的尾部，不能永久转native10。
- 每步先处理成功/终止及自然队列耗尽，再判断监测：必须处于5步监测点、当前plan_age>0、旧队列剩余至少5步、总预算余量至少C10、尚未干预且G0超过固定阈值。自然重规划边界不额外报警；不同H的最后合法cut按这些规则计算，不能把H10的285硬编码到所有H。
- 当前Q语义仍是10步候选后native10终局结局估计。H>10的固定Q属于部署分布变化，不每个H重训，也不按测试H另调半径。
- G0的historical_label_commitment=5与deployment_commitment=10单列；本轮不把旧G0悄悄改成新G10。MT50需要哪些组件重新适配由资产证据与分析端决定，不由执行端自行换目标。
- 原生Post/Velocity定义、mask、raw恢复、组内幅度和自身半径遵守2026-09-19算法文档；不用旧共同半径，不加入新Q接受门或按源选方法。
- 真机由用户负责。E8保留多底座MW与π0.5/LIBERO接口准备，外部方法矩阵不复制到E8。

## 2. 三种比较不得混名

1. E1同数据学习消融：五任务600源、同起点/架构/训练模块/优化预算，四损失×两个算子。L_ab=BCE+a*gain+0.5*b*pair。准备配置支持3个完整训练seed；不把ensemble成员当独立seed。
2. E3完整系统：共用冻结底座、原始训练池和测试协议；各方法保留原目标、输入表示与原生触发/引导频率，完整记账。每次采样都引导或多次截断可以保留，不能挂到G0一次触发后仍叫原生系统。
3. E6触发对照：仅收益/视觉异常两种触发，均接R、同H10和一次干预上限。用开发集匹配相近干预预算，测试不追平、不按结果调阈值。

异常误差按先前预测与后来到达的实际观测对齐，触发时不能访问未来图像。两个触发器按初态配对，其实际cut可以不同。

五任务Full和新增MT50训练Full按不同模型/数据身份记录，不能直接互换为E1基线。外部适配改了原论文底座或动作接口，在方法名和配置中标adapted。

## 3. 数据权限与split

- 公共数据池由已有示范、正常rollout、局部候选及真实后缀组成；各方法只读同一数据访问manifest，视图筛选及有效样本数独立记录。
- VLA-Corrector正常示范动态视图、GAF-v1 success-to-go/MSE视图、QGF chunk TD/IQL视图与本方法gain/pair视图各自保留目标，不能统一成BCE然后声称忠实原法。
- 原始parent episode下全部cut/source/候选/后缀放在同一split。任务/初态、父轨迹、分支、生成噪声及后缀身份可追溯。
- 真实轨迹转移不能跨候选/后缀拼接。只执行10步就不能构造“执行50步后”的next状态；奖励聚合与折扣按真实执行长度定义。
- 记录原始观测/图像引用及版本，不只保留本方法压缩PCA。历史bank缺失字段写明确缺口，不能用假图像/假next/末端标签复制补齐。
- 测试集在所有模型与开发规则固定后创建/运行；测试日志不训练模型。所有已揭晓历史held只能是历史/开发资料。
- 继承模型/预处理及训练历史单列。“共同新增数据”不等于全部训练数据相同；严格同完整数据比较需要可核查完整数据沿革。

## 4. 公共执行接口的验收语义

不在分析端指定具体Python类名。A负责发布数据/动作/事件合同的实际机器可读schema和最小样例，B提交能按同一合同消费/输出的adapter。

必须表达：
- 方法身份、环境/任务/底座、H/C/剩余预算、当前可部署观测历史、固定a0/噪声身份；
- 未引导新计划与最终执行raw动作，实际执行prefix，坐标/normalizer身份；
- 进入/返回/失败的完整VLA采样、flow前向、VLA反向、Q前后向与监测事件；
- 自然重规划、报警重规划、内部二次采样及真实chunk执行长度；
- 部署必要成本和研究诊断/恢复/审计成本分别归属；
- 技术错误、无报警、早成功、零梯度及未修改raw坐标原样记录，不混成任务失败或换源。

A10使用合成CPU样例校验schema、身份、分片及H/C逻辑；B10不需要等GPU主模型训练完成，可并行准备视图和adapter。实际加载/数值GPU验证在P10具体预检release中安排。

## 5. 日志与成本

episode表及event表最小字段见[DATA_LOG_CONTRACT_V1](DATA_LOG_CONTRACT_V1.md)。同一份日志派生E5，不新增任务分支。
- 一次正常R/P/V入口完整采样为1/1/2；flow前向按真实事件记录，不由方法名硬填。
- 部署episode成本含该方法自己的前缀、入口和后缀，不因采集复用分摊a0；N旁路寻找cut的D/G0不算N部署成本。
- calls-per-success=全部评测调用/成功次数，失败代价包含；MT50任务宏权重和成功率一致。零成功不能记零成本。
- GPU异步计时不等于CPU提交时间，父/子计时不重复相加；重建时间标估计，不冒充独立整episode墙钟。
- 预定单实例计时子集占用已有评测样本，不新增rollout。固定同一主机/GPU型/精度/batch/并发/预热；跨主机不直接除出加速倍数。

A/B分别只写work/A、work/B、results/A、results/B、receipts及本节点identity；不原地改共享环境，不改旧封存。
