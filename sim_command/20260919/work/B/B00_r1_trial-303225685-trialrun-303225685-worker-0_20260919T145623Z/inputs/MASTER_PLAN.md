## 3. 数据、代码与评测分片

### 3.1 同数据的含义

共用原始示范/rollout/局部分支池；各自保留动态预测、MSE或IQL/TD目标。保存观测、动作、真实执行prefix、奖励、成功时刻、next观测、终止/截断、原episode和source身份。当前仅含候选终局均值的bank不能自动满足所有网络。

所有同原episode的cut、候选与后缀归同一split。测试日志不回流训练。初始化及历史数据不同必须列出；旧A4000与旧VLA-Corrector直接复用时不能宣称全部训练数据相同。

E3优先使用已本地复现VLA-Corrector；GAF-v1或QGF只锁定一个主近邻，具体由B00/B10的版本与字段审计决定。公开代码和训练目标见[总方案E3](../../docs/Experiment_plam.md)。

### 3.2 代码与文件所有权

A负责公共runner、日志和本方法；B负责外部方法及E8适配。准备改动先在work/A、work/B或独立checkout内进行，提交补丁/快照供接口整合。两端不同时修改公共文件，不覆盖原复现代码或已封存checkpoint。共享Python环境不原地升级，依赖差异使用各自隔离环境并报告。

公共训练池的实际数据清单由A写到results/A/<run_id>/data_manifest.json；分析端在manifests/发布指向它的路径、SHA及冻结身份，A不直接写分析端目录。B仅写分配给自己的分片及视图索引。不可变产物用唯一run目录与SHA标识，写完后原子发布complete文件；发布后只读。

### 3.3 评测分片

分析端生成全局eval manifest并对每个task内的source序号交错分配给A/B，保证两台都覆盖所有任务；最终由显式shard列表决定归属，执行端不临时计算或抢占对方分片。

一个source包包含该源的所有要求方法、H和后缀身份；同H的R/P/V配对cut，跨H只配初态。E3可以按冻结清单稍后补同一主机/同一源的外部方法，但不能因已见测试成绩修改它的配置。优先在P20前完成全部选模。

硬件不同时，记录host并检查分层效果；不把Post全放A、外部方法全放B。统一时延表指定同一个主机/GPU型的预定计时子集；B上的运行耗时可报资源，不能直接除以A的延迟得加速比。

## 4. 样本和预算如何冻结

当前用户要求先安排任务，且B的硬件、可用checkpoint及完整轨迹字段未知，因此不发布虚构的GPU命令或总预算。

- A00/B00交付库存及缺口；A10/B10交付预检/训练/评测的计数与时间报价。
- E4/E3按50任务等额分配新物理初态；E1/E6按五任务等额；后缀数和训练seed在正式release中写成具体整数。
- E1建议四损失×三个完整训练seed，不把四成员ensemble当seed；五任务Full不能与不同训练数据的MT50 Full混成损失比较。
- E4 16个单元、E3新增2个外部方法单元均不依赖最终样本数而改变；无报警和合法复用可降低实际执行量，但不改变结果分母。
- release必须列明确的train/development/test source数量、每源候选与后缀、优化上限、simulator attempts、模型调用、重试上限和停止条件；没有上限的任务不能自动开始正式计算。
- 数据采集、生成恢复、预检、技术失败均计成本。旧49507/50000账本的493余量不是新任务预算，不改旧账本。

分析端可在用户已授权的仿真研究范围内据回执冻结下一任务；不要求用户为每个可逆工程步骤重复确认。超出已确定方法范围或不可接受资源缺口时再反馈，而不是由执行端自行改实验。

## 5. 调度、回执与GPU政策

执行端首先将节点身份写入nodes/<A或B>/identity.json；领取自己的任务写receipts/<节点>/<task>_ACK.json，含hostname、会话ID、task revision、start UTC。运行中的心跳只写自己的文件。共用CONTROL/TASK_BOARD仅分析端修改。

当前CONTROL mode=prepare，仅A00/B00可执行。后续正式命令必须同时匹配本campaign、task、revision、protocol/data/code/model SHA、host、shard与预算；旧READY文件名不构成放行。

重启先检查原run目录、PID与进程启动时间、已有完成记录，再续跑缺失单元，不从头重放。心跳过期不自动接管；跨机迁移由分析端重新分配并保留原身份。技术失败保留原记录，不反复换seed重试直至成功。

两机分别管理本地/tmp/gpu_occupancy_guard，不能共享PID/锁。按[工作区GPU政策](../../../AGENTS.md)检查guard；正式GPU命令由gpu_occupancy_lifecycle.sh run --包装。release明确wave_id及参与主机：整个正式波次期间，参与主机的所有holder停算，包括提前完成的GPU；A/B联合波次用完成屏障保持生命周期预约，不能某主机子任务完成就恢复holder。该波次所有参与任务退出（含失败）后统一结束预约并恢复。仅单机参与的独立波次按其本机结束，不干涉未参与主机的正常occupancy。不终止无关计算进程。A/B共享日志路径存在冲突风险，执行端核查按主机区分记录，不能将对方日志当本机状态。

A可使用本机Codex queue给分析端发“任务ID＋摘要＋回执路径”；B仅写共享回执与待办，不能尝试连接A的会话ID。分析端读取短报告、manifest和逐源表；代码细节留给执行端。

任务执行前、每个训练/评测子批次边界检查CONTROL和任务revision。没有新release时不跑后续正式任务；完成可执行准备后可结束当前轮并等待新共享任务，不要求无意义长时间占用对话。

## 6. 真机边界

真机任务、设备、数据和一次验证设置由用户决定和执行。这里不新增机器人命令、不安排公开方法真机对照，不将一组真机展示扩写为跨方法领先证据。分析端后续可接收用户真机结果做统一统计；不阻塞当前两服务器仿真准备。
