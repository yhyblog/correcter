# 持久队列合同 v1

这是一项执行方式迁移，落实用户2026-09-21指令。取消正常同阶段批次之间的人工投递、CPU准备和计算release循环；只在改变方法/预算/数据划分或处理未预见异常时交分析决策。

## 1. 持续授权和迁移

`AUTHORIZATION_V1.json`一次授权A实现与部署公共程序、B接入及冻结待执行共同池。执行端可在隔离目录实现、运行必要CPU/fake检查、发布程序SHA、部署后台服务并完成无GPU的控制面自检；符合下述机器门后自动开始既定源，不需再申请一轮安装/计算授权。不得将尚未部署描述为已完成。

当前A Batch3仍使用原冻结入口直到全部正式后代退出并完成发布/清理；不得中断、热改文件、套外层新锁或重复命令。旧14份已关闭release永久不复用。新服务可先启动只读等待模式，迁移到新协议必须保存旧波次退出屏障。旧CONTROL/原release/回执不覆写；新队列的每节点活动记录是后续任务的授权入口，旧全局单一active字段不用于A/B并行派单。

## 2. 任务与领取

固定集合为原50任务×(8 train＋2 development)=500源。源键`(task,split,ordinal,cut)`不可改变；17已处理源含normal-only直接终结，Batch3的8源保持既有release独占，剩余475才可派生队列作业。原始身份/seed沿用，不补p04；Batch3中只有已证明从未启动、且原wave已结案释放的槽可由独立明确处置转回pending，默认不回填。

task ordinal这次明确冻结为task名称ASCII排序0…49，与wrapper ID、语言index和字典index分开保存。train owner=`A/B[(ordinal//2)%2]`；development owner=`A/B[(task_ordinal+ordinal)%2]`；cut=`(5,55)[ordinal%2]`。真实dev尚为0，本次不会改变已产生样本归属。每节点固定排序`(train先于development,ordinal,task ASCII)`；不得按标签、收益、成功率或耗时改顺序。

每批最多8父源，每节点最多2并行父源，每源最多15个顺序cold分支，算法/状态闭包/噪声/终局/双repeat及标签协议沿用。尾批按真实剩余数量报价，不补齐。B首次实际采集以其第一个原计划源、并发1验证本机加载/状态/退出/发布；通过后自动按并发2推进，不增加诊断源或额外短GPU实验。

后台在总授权内自动派生唯一batch/run/shard/command/claim和完整resource vector，不再由分析逐批手写release。每个command至多一次；领取和进入分开落盘。共享源领取用原子排他创建/等价事务；节点owner、run UUID、boot身份和代码/源/预算SHA全部绑定。租约超时不能作为重复执行依据。

## 3. 占卡与进程生命周期

每节点一个supervisor，在一次外层预约中运行queue-drain；各批入口继承预约FD/所有权，不再次调用冻结guard.run抢formal.lock，不调用旧Batch3 launcher。旧launcher先claim再预约且等待每批occupancy恢复，必须以新queue-aware入口替代这一层，复用数值采集器。

有正在执行任务或可立即衔接的已批准任务时，本机全部holder持续停算，包含加载、CPU整理、校验、发布阶段。每批自己的进程组及后代全部退出、数据与成本发布后可进入下一批；按批记录`restoration_deferred_to_queue`。不得在批次空隙或GPU提前闲置时启动holder。只有没有可执行任务且owned进程/发布/清理屏障全部结束后才释放预约、统一恢复holder。仅有被依赖阻塞的作业视为无可执行任务，不无限停卡；后台空轮询本身不是正式任务。

stop先禁止新admission，再按冻结策略排空或清理本机owned进程；不得终止无关进程。异常也执行退出/发布/恢复屏障。每节点日志、锁、状态含host和node，不依赖旧未分host的共享guard日志判断跨机状态。

服务须脱离会话：stdin断开、独立session、文件日志、单例锁和可靠子进程回收；优先已有可用的服务管理器，否则提供明确的后台启动与恢复命令。用无GPU的两个合成作业验证启动父会话退出后仍继续、结果落盘与幂等再启动。机器/容器重启不是终端关闭：若无平台启动钩子，明确需要一次重新启动服务。重启先对账活跃job/boot/PID启动身份，未知执行进入blocked，不能删除锁文件或重跑已消费命令。

## 4. 自动技术验收和失败分级

每批自动检查源/split/模型与代码身份、账本闭合、操作上限、合法终局、双repeat资格、闭包字段/MJB、进程退出、原子发布及manifest。通过后追加不可变machine-validated索引并领取下一批，不等聊天回执。保留raw，明确它与论文效果结论/全物理等价的区别。

- cut前成功、s300无成功、承诺内成功：按既定语义结案，合法partial继续下一源；缺配对为null/mask=false，不补源。
- 父源局部技术失败且费用/退出/清理完整：该源停止，证据保留，继续固定下一源；同一技术故障签名连续3个父源则暂停该节点，防止系统性浪费。失败不标负样本。
- 本机容量、设备/运行环境、清理失败或未知执行：暂停本节点新领取并处理退出屏障。
- 源冲突、split污染、科学协议/权重身份漂移、共享证据损坏、总预算耗尽、全局stop：暂停整个阶段。

分析仍审查科学结论和异常；正常批次不等待人工验收才能接续采集。进入训练/评测只在该阶段的模型初始化、损失/seed/预算/选模及P20评测协议已一次冻结时自动解锁。当前授权不包含新训练、梯度/critic调用或正式比较评测。

## 5. 资源与存储

每源116操作向量沿已验证cold采集模板，初始化逐项使用冻结50任务表；`PER_TASK_PARENT_BUDGETS_V1.json`、`AGGREGATE_LIMITS_V1.json`提供确定上限。总待执行475源至多7125个cold attempt；未用额度不复用为新源。调度/guard/服务监控成本单列，不能混成策略采样或宣称整个进程精确GPU秒为0。

独立接受本阶段的bounded存储监测缺口：quota/独占预留、范围外或unlinked临时文件、监测间超调、RSS/VRAM峰值、实际IO仍未知。每批重新准入；8源批保守要求93,952,475,136B及564096inode，本机每源11,609,841,664B预算、批辅助512MiB、free floor512MiB。尾批按同公式；A/B在共享存储用同一原子预约账本扣除对方未释放保守额度，防止同时承诺相同空间。预约账本不是文件系统硬quota，剩余容量下降照原门暂停。不得因容量不足自动删数据或权重；清理仍按明确清单单独执行。

无需重复50源码审查、旧测试全集或历史大权重hash；真实载入的现有身份/输入检查不放松。只对调度/授权/接口变更做有意义的定向检查：重复领取、跨节点互斥、断会话、未知执行恢复、连续批次不恢复holder、空队列恢复、容量/协议失败暂停。方法数值、15cold、半径、Q门、split和采样逻辑不改。

## 6. 状态和一次接入

各节点写`JOIN_ACK.json`、`DAEMON_READY.json`及原子heartbeat（node/host/boot/service PID与启动时间/package SHA/总授权SHA/当前job/claim/最近终局/blocked reason/reservation/holder模式）。READY必须依据实际后台存活与合成控制面检查，不是仅文件生成。任务RESULT写共享目录即可，无需开对话投递每一批。

A通过既有本机会话收到一次bootstrap。B没有已安装服务或远程通道时，共享文件不会自行唤醒机器；需要用户给B执行会话发送一次接入任务。若A包未到，B须将仅验证固定READY入口的join-waiter后台化；包符合本授权并自检通过后自行接入，不要求用户保持窗口等待。等待不算正式GPU工作，有可执行CPU/GPU作业时按本合同停holder。
